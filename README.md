## 🗄️ Database Schema Design & Indexing

I’m particularly interested in designing database schemas that maintain data integrity, support application requirements, and perform well as data grows.

### Start Here — Core Topics

- **Database Relationships:** One-to-one, one-to-many, and many-to-many relationships.
- **Normalization vs. Denormalization:** Balancing data consistency, duplication, and query efficiency.
- **Keys and Constraints:** Primary keys, foreign keys, unique constraints, and referential integrity.
- **Indexing:** Single-column indexes, composite indexes, and selecting indexes based on query patterns.
- **Query Analysis:** Reading `EXPLAIN` and `EXPLAIN ANALYZE` to understand query plans and investigate slow queries.

### Practical Database Engineering

- Relational schema design and data modeling
- PostgreSQL and SQL query development
- SQLAlchemy ORM and database migrations
- Index creation and schema evolution
- Query optimization and reducing unnecessary database operations
- Pagination and efficient data retrieval
- Transactional writes and data consistency
- Understanding read/write patterns and their performance implications

My goal is to make database decisions based on the data model, query patterns, correctness, and measured performance rather than adding complexity without a clear need.
